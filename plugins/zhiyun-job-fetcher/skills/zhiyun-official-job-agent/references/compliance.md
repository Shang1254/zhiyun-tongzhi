# 运行合规 / 调度 / 输出标准 / 错误修复 规范（落地版）

## 1. 运行合规规则

- **每日 0 点低峰运行**：`server/src/cron.js` 中 node-cron「0 0 * * *」自动全量采集；手动白天运行仅打印提示不阻止。
- **礼貌限速**：单站点请求间隔 3-8 秒随机、并发 1，避免固定机器节奏。
- **robots 协议**：每次运行先获取并遵守 robots.txt，Disallow 直接跳过并留日志。
- **可识别 UA**：`ZhiyunTongzhi-PublicJobBot/1.0`，不伪装浏览器，让对方站点随时能识别并联系我方。
- **熔断**：403/429/连续失败自动熔断，当日停止该站点。

## 2. 数据校验与输出标准

- **增量去重**：以岗位ID（`mohrss_{acb200}` / `wllm_{id}`）检查库内已存在则跳过。
- **虚假岗过滤**：入库前全部经过虚假岗评分引擎复检（`server/src/services/jobFilter.js`），可解释评分。
- **隐私剔除**：mohrss 联系人字段（aae004/aae005/aae006）不存储；岗位库不存任何用户敏感数据。
- **编码**：统一 UTF-8（SQLite / HTTP JSON 天然无 BOM 乱码问题）；如需 CSV 导出场景用 utf-8-sig。
- **岗位全字段结构化输出**：标题、单位、地点、薪资、学历要求、来源（source）、原文链接（applyUrl）；入库后前端/APP 自动带「✔官方渠道」标签。

## 3. 错误自动修复规范

- **重试**：失败自动重试 3 次，指数退避 3s / 9s / 27s。
- **熔断**：重试耗尽当日熔断该站点，不无限纠缠。
- **日志**：异常日志本地留存于 `server/data/logs/`，**不上传任何对外服务**。
- **报告**：每次运行追加写入 `server/data/reports/fetch-YYYY-MM-DD.md`（同日多次运行留痕）。

## 4. 定时调度规则

- `00:00` 官方岗位采集（cron「0 0 * * *」）
- `03:00` 岗位库复检（重新评分虚假岗 + 标记过期岗位）
- `09:00` 按用户画像生成当日推荐
- 完成后自动生成当日更新报告（见上）。

## 5. 「零封禁」决策记录（2026-11，永久约束）

用户曾提供「零封禁全套实战技巧」（代理池轮换 / 随机会话隔离 / 随机UA池 / 模拟人类浏览路径 / Playwright 指纹伪装）。处理结论：

**采纳（基础合规防封——这本身就是「零封禁」的正道）**

| 技巧 | 处理 |
| --- | --- |
| 严格遵守 robots 协议 | ✅ 运行时获取 robots.txt，Disallow 直接跳过并留日志 |
| 锁定低峰时段（每日 0-4 点） | ✅ cron 固定 0 点；白天手动运行打印提示不阻止 |
| 请求间隔 3-8 秒随机 | ✅ 区间随机，避免固定机器节奏 |
| 429/503 指数退避重试 | ✅ 3/9/27 秒退避，重试 3 次后熔断当日该站 |

**拒绝（代理轮换与行为伪装——属检测规避，不做）**

| 技巧 | 拒绝原因 |
| --- | --- |
| 轮换代理池 / 按URL取模换出口IP | 目的是规避站点封禁措施。对当前两个数据源毫无必要（可识别UA+限速实测 40+ 次零封禁）；对已 403 的 ncss 是错误药方——正确路径是官方机构接口对接，不是换IP硬闯 |
| 每代理绑定独立会话 | 服务于上述代理轮换，随之不做 |
| 随机真实浏览器UA池 / 补全伪装请求头 | 伪装成浏览器访问是欺骗性标识；本项目承诺可识别UA，让对方站点随时能识别并联系我方 |
| 先逛首页 2 秒再爬列表详情的「人类路径」 | 以绕过自动化检测为目的的行为伪造 |
| Playwright 设备指纹伪装 | 同上；且现代 WAF 靠行为分析，伪装成功只是延迟被封，被识破后 IP 段可能被永久拉黑，反而断送后续官方对接可能 |

**一句话**：这两个数据源是政府公共就业服务平台与高校官方系统，「零封禁」靠的是让对方愿意持续开放，而不是让对方认不出你。
