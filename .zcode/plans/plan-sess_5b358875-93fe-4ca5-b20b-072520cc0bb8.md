# 「拼车同行」功能模块实施计划（公益信息公告板定位）

## Context
民办生跨市回家/返校/跨城面试的拼车是真实高频需求，作为「知云同职」第四个功能模块上线。**定位严格限定为公益信息公告板**（非撮合方、不收费、不担保出行安全）：用户主动发布拼车信息并自愿公开联系方式，平台提供展示、筛选、打码保护、防滥用过滤、过期清理与删除能力。与既有隐私原则的衔接：岗位画像仍维持匿名零敏感；拼车联系方式属**用户主动公开**内容，通过"发布时明示公开范围 + 列表打码 + 点击查看 + 删除令牌"四道设计落实知情与可控。

## 一、数据层 `server/src/db.js`
新增 rides 表：`id, type(找车|带人), from_city, to_city, ride_date, ride_time, seats, contact_type(电话|微信), contact(用户主动公开), note(≤200字), delete_token_hash(sha256), status(active|hidden), created_at`。轻量迁移沿用 jobs 表模式。

## 二、内容安全 `server/src/services/rideGuard.js`
- 发布反诈过滤：命中黑名单词（刷单/贷款/代购/兼职缴费/赌等）拒绝发布并提示
- 字段校验：必填项、长度、日期格式、seats 1-6、联系方式格式（手机号或微信号基础规则）
- 免责声明文案常量（发布页/详情页复用）

## 三、API `server/src/routes/rides.js`
- `POST /api/rides` 发布 → rideGuard 校验 → 入库（token 明文一次性返回，库中只存 sha256）
- `GET /api/rides?from=&to=&date=` 列表：仅 active 且未过期（ride_date≥今天），按日期近先排序；**联系方式打码**（138****1234 / 微信 wx***后续隐藏）
- `GET /api/rides/:id` 详情：完整联系方式（前端点击"查看完整联系方式"时调用）
- `DELETE /api/rides/:id`：body.token 的 sha256 与库中比对，匹配才删
- `POST /api/rides/:id/report` 举报 → status=hidden（下架待处理）
- `GET /api/rides/meta/stats`

## 四、前端 `web/`（第四个 Tab「🚗 拼车」）
- `index.html`：TabBar 四项 + `page-ride`（发布表单卡片：类型切换/城市/日期/时段/人数/联系方式类型+号码/备注 + 免责声明勾选；列表区含"我的发布"分段）
- `js/ride.js`：发布（deleteToken 存入加密保险库 ZYVault）、列表渲染（打码 + 点击查看完整）、我的发布（凭本地 token 列出并可删）、举报入口
- `css/app.css`：沿用蓝白风格扩展拼车卡片样式
- TabBar 改四项的布局微调

## 五、过期清理 `server/src/cron.js`
03:00 复检任务中追加：rides 表中 `ride_date < 今天` 超过 7 天的物理删除（更近的仅从列表过滤已由查询保证）。

## 六、文档与合规
- `AGENTS.md` 第4条隐私规则修订：明确区分"系统收集（岗位画像，继续匿名）"与"用户主动公开（拼车联系方式，明示+打码+可删）"
- 免责声明上线：平台仅提供信息展示、不参与组织拼车、出行安全与费用自理、谨防 along-route 诈骗（复用防骗提醒话术）
- SKILL.md 无需改（采集技能 unrelated）
