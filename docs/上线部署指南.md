# 知云同职 · 海外上线部署指南

> 目标：把一个公益求职站放到**境外服务器 / 境外免费平台**上，国内同学与海外华人都能打开。
> 本文只讲真实可执行的两条路线，外加一条"立刻能看"的临时预览路线。

---

## 〇、先选路线

| 路线 | 能力 | 成本 | 适合 |
| --- | --- | --- | --- |
| **A. 纯静态**（GitHub Pages / Cloudflare Pages / Netlify） | 岗位库（导出时的真实数据）、简历生成、PDF 导出、防骗检测、PWA 离线 | 永久免费，无需服务器 | 只想让大家打开就能查岗、做简历 |
| **B. Node 动态**（Render / Fly.io / 境外 VPS + Docker） | A 的全部 + 拼车发布、每日推荐、岗位每日采集 | 免费额度或 ~$5/月 | 要拼车板块和自动更新的真实岗位库 |
| **C. 临时隧道**（cloudflared / ngrok） | 等于 B，但依赖你自己电脑开机 | 免费 | 先给别人看一眼、答辩演示、临时验收 |

**关键区别**：静态版没有 `/api`，拼车板块会提示"未连接服务"，每日推荐在前端按画像即时挑选；动态版才有完整后端。

---

## 一、路线 A：纯静态站点（最快，10 分钟）

### 1. 生成静态包

```powershell
cd server
npm run build:site          # 产物在项目根目录 dist\site
```

产物结构：

```
dist/site/
├── index.html / 404.html       # 首页（404 兜底，GitHub Pages 深链不白屏）
├── manifest.webmanifest        # PWA 清单，可"添加到桌面"
├── sw.js                       # 离线缓存
├── icons/                      # 192/512/maskable 图标
├── css/ js/ vendor/
└── data/seed-jobs.json         # 从数据库导出的真实岗位（含官方来源与原文链接）
```

`data/seed-jobs.json` 里的岗位是**导出那一刻**的库内容。岗位库更新后要重新 `build:site` 并重新上传，这是静态版的固有代价。

### 2. 发布到 GitHub Pages（推荐，永久免费）

```powershell
# 一次性：登录 GitHub（浏览器里点一下授权）
gh auth login

# 建仓库并推送静态产物（把 shangzixuan 换成你的用户名）
cd dist\site
git init
git add -A
git commit -m "deploy: 知云同职静态版"
git branch -M main
gh repo create zhiyun-tongzhi --public --source=. --remote=origin --push

# 开启 Pages（分支 main，根目录）
gh api -X POST repos/{owner}/zhiyun-tongzhi/pages -f source[branch]=main -f source[path]=/
```

访问地址：`https://<用户名>.github.io/zhiyun-tongzhi/`
> 本项目全部资源用相对路径，放在子路径下也能正常工作。

### 3. 发布到 Cloudflare Pages（海外访问最快）

```powershell
npm i -g wrangler
wrangler login                       # 浏览器授权
cd dist\site
wrangler pages deploy . --project-name=zhiyun-tongzhi
```

得到 `https://zhiyun-tongzhi.pages.dev`。`_headers` 文件会被 Cloudflare 自动识别（安全响应头 + 缓存策略）。

### 4. 发布到 Netlify（拖拽即可）

打开 https://app.netlify.com/drop ，把 `dist\site` 整个文件夹拖进去，立刻得到 `https://xxx.netlify.app`。

### 5. 静态版想接后端（可选）

如果后端已经按路线 B 部署在 `https://api.example.com`，重新构建一次即可让静态站调用它：

```powershell
npm run build:site -- --api-base=https://api.example.com
```

这样静态站负责页面与离线兜底，后端负责拼车、每日推荐、真实岗位接口。

## 二、路线 B：Node 动态部署（完整功能）

### 方式 1 · Render（有免费额度，最省事）

1. 把整个项目推到 GitHub（含 `render.yaml`）。
2. Render → New → **Blueprint** → 选中该仓库，自动读取 `render.yaml`。
3. 部署完成后得到 `https://zhiyun-tongzhi.onrender.com`。

注意：
- 免费实例 15 分钟无访问会休眠，首次打开要等 30-60 秒冷启动。
- 免费实例磁盘是临时的，重启后 SQLite 回到内置演示库；要保留采集岗位与拼车信息，加一个 Persistent Disk（挂载 `/var/data`，`ZY_DATA_DIR` 已指向该路径）。

### 方式 2 · Fly.io（有持久卷，冷启动少）

```powershell
fly auth login
fly launch --no-deploy --copy-config --name zhiyun-tongzhi
fly volumes create zhiyun_data --size 1 --region sin
fly deploy
```

`fly.toml` 已配置：新加坡区域、512MB、`/data` 持久卷、健康检查 `/api/health`、自动 HTTPS。

### 方式 3 · 境外 VPS + Docker（最可控）

以 Ubuntu 22/24 为例：

```bash
# 1) 装 Docker
curl -fsSL https://get.docker.com | sh

# 2) 拉代码（或直接 scp 整个项目）
git clone <你的仓库地址> zhiyun && cd zhiyun

# 3) 起服务（SQLite 落在命名卷上）
docker compose -f deploy/docker-compose.yml up -d --build

# 4) 反代 + 自动 HTTPS（把域名换成你的）
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile   # 先改里面的域名
sudo systemctl reload caddy
```

没有 Docker 也可以直接用 Node：

```bash
# Node 20+，建议用 nvm 装 Node 22
cd server && PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm ci --omit=dev
NODE_ENV=production ZY_DATA_DIR=/var/lib/zhiyun node src/index.js
```

配一个 systemd 常驻（`/etc/systemd/system/zhiyun.service`）：

```ini
[Unit]
Description=Zhiyun Tongzhi
After=network.target

[Service]
WorkingDirectory=/opt/zhiyun/server
Environment=NODE_ENV=production
Environment=ZY_DATA_DIR=/var/lib/zhiyun
Environment=TZ=Asia/Shanghai
ExecStart=/usr/bin/node src/index.js
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

### 部署后必做

```powershell
# 部署前自检（在服务器上跑）
cd server && node src/selfcheck.js

# 线上冒烟检查（本机跑，目标换成线上地址）
cd server && npm run smoke -- https://你的域名
```

冒烟脚本会检查：首页渲染、岗位卡数量、四个 Tab、防骗检测、PWA manifest、控制台报错，并截图到 `dist/`。

## 三、路线 C：临时公网预览（本机隧道）

适合"先让别人看一眼"：服务跑在自己电脑上，隧道给一个公网 https 地址。

```powershell
# 1) 起服务
cd server; npm start

# 2) 另开一个窗口，起隧道（cloudflared 无需注册）
cloudflared tunnel --url http://localhost:3000
```

输出里会出现 `https://<随机词>.trycloudflare.com`，境外、国内均可访问（国内访问稳定性取决于本地网络质量）。

- 电脑关机 / 隧道进程结束 → 地址立即失效，**不适合正式上线**。
- 想固定地址：注册 Cloudflare → 建 Named Tunnel → 绑自己的域名（免费）。

## 四、域名与合规

- **境外服务器不需要 ICP 备案**；一旦换成中国大陆服务器 / 大陆 CDN，就必须备案，招聘类内容还要额外资质。
- 域名建议直接用 `pages.dev` / `github.io` / `onrender.com` 的免费子域，先跑起来再考虑买域名。
- HTTPS 必须开：PWA 的 Service Worker 只在 https（或 localhost）下生效。GitHub Pages、Cloudflare Pages、Render、Fly 都自动带证书。

## 五、上线检查清单

- [ ] `https://<域名>/api/health` 返回 `ok:true`（动态版）
- [ ] `https://<域名>/` 能看到岗位列表，搜索/筛选正常
- [ ] 手机浏览器"添加到主屏幕"能出图标（PWA）
- [ ] 断网再打开：静态版仍能看岗位、做简历、跑防骗检测
- [ ] `/api/jobs/meta/stats` 的虚假岗数量 > 0（说明规则引擎在跑）
- [ ] 页面底部"永久免费、无广告"声明可见
- [ ] `npm run smoke -- https://<域名>` 6/6 通过

## 六、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `better-sqlite3` 安装报 `node-gyp` 错 | 镜像里缺编译环境。用 `deploy/Dockerfile`（基于 bookworm-slim，装预编译包），或 `apt install -y python3 make g++` |
| 云上定时任务时间不对 | 容器默认 UTC。已在镜像与配置里设 `TZ=Asia/Shanghai`，自建环境记得也设 |
| 免费实例第一次打开很慢 | Render 免费版休眠冷启动，正常；介意就换 Fly 或 VPS |
| 重启后岗位库变回演示数据 | SQLite 在临时磁盘上。挂持久卷并把 `ZY_DATA_DIR` 指过去 |
| 静态站拼车页报错 | 静态版没有后端，属预期；按路线 B 部署后端后 `build:site --api-base=...` |
| 国内打开 GitHub Pages 很慢 | 换 Cloudflare Pages 或自建境外 VPS + Caddy，两者国内速度更稳 |
