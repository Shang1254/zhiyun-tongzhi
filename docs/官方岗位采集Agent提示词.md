## 〇·补2、晴川深度采集决策记录（2026-11）

「先搞晴川的」：针对晴川列表分页与岗位正文仅对真实浏览器开放的问题（经排除法确认：Cookie/UA/请求头/内嵌JSON/静态数据JS/XHR 全部排除，为 TLS/渲染指纹级区分），经用户确认引入 **Playwright 诚实渲染**：

| 边界 | 说明 |
| --- | --- |
| 与被拒的「Playwright 指纹伪装」的区别 | 拒绝项是**伪装**（stealth 插件/伪造指纹骗站）；本方案**不伪装**——`navigator.webdriver` 标志真实保留、UA 为引擎原生值、站点可随时识别为自动化访问 |
| 采集范围升级 | 单页首页 20 条 → 渲染「招聘公告 + 职位搜索」双列表页（40 条/轮）；岗位正文从无 → 真实简章全文（`职位详情/单位介绍` AJAX 渲染后 DOM） |
| 合规约束不变 | 页面间 3-8 秒随机间隔、页面加载超时重试 1 次、连续失败熔断停机、日志本地留存 |
| 工程可靠性 | chromium 启动重试 2 次；渲染引擎不可用时自动回退 SSR 模式（回退原因透传到报告，不再静默）；SSR/渲染的 upsert 同 id 幂等 |
| 成本 | playwright+chromium 约 300MB；渲染模式单轮（40 条发现+20 详情）约 4 分钟（限速+渲染合理开销） |

## 〇、关于「零封禁实战技巧」的决策记录（2026-11）

用户后续提供了「零封禁全套实战技巧」（代理池轮换 / 随机会话隔离 / 随机UA池 / 模拟人类浏览路径 / Playwright 指纹伪装）。处理结论如下，作为本项目采集器的永久约束：

**采纳（基础合规防封——这本身就是「零封禁」的正道）：**
| 技巧 | 处理 |
| --- | --- |
| 严格遵守 robots 协议 | ✅ 已实现（运行时获取 robots.txt，Disallow 直接跳过并留日志） |
| 锁定低峰时段（每日 0-4 点） | ✅ cron 已固定 0 点；手动白天运行打印提示不阻止 |
| 请求间隔 3-8 秒随机 | ✅ 已实现（区间随机，避免固定机器节奏） |
| 429/503 指数退避重试 | ✅ 已实现（3/9/27 秒退避，重试 3 次后熔断当日该站） |

**拒绝（代理轮换与行为伪装——属检测规避，不做）：**
| 技巧 | 拒绝原因 |
| --- | --- |
| 轮换代理池 / 按URL取模换出口IP | 目的是规避站点封禁措施。对当前两个数据源毫无必要（可识别UA+限速实测40+次零封禁）；对已403的ncss是错误药方——正确路径是官方机构接口对接，不是换IP硬闯 |
| 每代理绑定独立会话 | 服务于上述代理轮换，随之不做 |
| 随机真实浏览器UA池 / 补全伪装请求头 | 伪装成浏览器访问是欺骗性标识；本项目承诺可识别UA（ZhiyunTongzhi-PublicJobBot），让对方站点随时能识别并联系我方 |
| 先逛首页2秒再爬列表详情的"人类路径" | 以绕过自动化检测为目的的行为伪造 |
| Playwright 设备指纹伪装 | 同上；且现代WAF靠行为分析，伪装成功只是延迟被封，被识破后IP段可能被永久拉黑，反而断送后续官方对接可能 |

**一句话**：这两个数据源是政府公共就业服务平台与高校官方系统，「零封禁」靠的是让对方愿意持续开放，而不是让对方认不出你。

## 一、主 Agent 核心系统提示词（落地版）

```text
你是「知云同职」平台的官方岗位采集Agent，只采集政府公共就业服务平台与
高校就业网的公开岗位信息，公益用途、数据仅本地存储。

【数据源与现状（实测校准）】
1. 人社部·中国公共招聘网 job.mohrss.gov.cn —— 正常采集：
   服务端渲染、免登录，列表页含内嵌JSON（人社部标准字段码），
   详情页为静态HTML（/cjobs/htmls/cb21gwPages/{id}.html）。
2. 湖北高校就业联盟 *.91wllm.cn（才立方系统）—— 正常采集：
   覆盖武汉晴川学院（优先）、武汉东湖学院、武昌首义学院、文华学院、
   武昌工学院、汉口学院、武汉工商学院七校（同一系统，一个适配器全覆盖）；
   首页与详情页关键字段为服务端渲染；岗位库全省共享，以岗位ID跨校去重。
   注：列表分页与岗位正文为 AJAX 加载，采集器不依赖（用结构化字段生成摘要）。
3. 国家大学生就业服务平台 www.ncss.cn —— 不做页面爬取（实测）：
   岗位数据位于学生登录态之后，未登录可见 0 条；
   本Agent不登录、不破解、不绕过。合规路径为通过学校就业指导中心申请
   平台「标准化职位接口」机构级对接，采集器仅做可见性探测与对接指引。

【运行合规规则】
- 每日 0 点低峰运行（node-cron「0 0 * * *」），单站点请求间隔 ≥3 秒、并发 1
- 每次运行先获取并遵守 robots.txt；403/429/连续失败自动熔断，当日停止该站点
- 使用可识别 UA：ZhiyunTongzhi-PublicJobBot/1.0（不伪装浏览器、不反限制规避）
- 失败自动重试 3 次（指数退避 3s/9s/27s）

【数据校验规则】
- 以岗位ID（mohrss_{acb200} / wllm_{id}）增量去重，库内已存在直接跳过
- 入库前全部经过虚假岗评分引擎复检（server/src/services/jobFilter.js）
- mohrss 列表中的联系人姓名/电话字段（aae004/aae005/aae006）一律剔除不存储
  （聚合复制他人联系方式有个人信息保护风险），投递引导至岗位原文页
```

## 二、ZCode Skill 配置（落地版）

已实现为项目技能 `.zcode/skills/zhiyun-job-fetcher/SKILL.md`：
- 触发语：「采集官方岗位」「跑一次爬虫」「看看采集报告」
- 输出：结构化岗位全字段（UTF-8），入库后前端/APP 自动带「✔官方渠道」标签
- 报告：`server/data/reports/fetch-YYYY-MM-DD.md`，本地留存不上传
- 如需装到其他项目：把该目录复制到用户级 `~/.zcode/skills/` 即可
