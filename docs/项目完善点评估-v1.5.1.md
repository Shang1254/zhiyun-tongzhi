## 二、还存在的问题（按优先级）

### P0 · 上线期间就该补的

**1. 拼车举报可被滥用（任何人能下架任何人的帖子）**
- 【代码】`POST /api/rides/:id/report` 只做一次 `status='hidden'`，不校验理由、不区分举报人。
- 影响：脚本遍历 id 就能把整个拼车板清空，且没有记录是谁举报的。
- 建议：新增 `ride_reports(ride_id, ip_hash, reason, created_at)`；同一 IP 同一贴只记一次；累计 3 个不同来源才自动下架，否则进「待审」；管理员接口可查。
- 验收：同一 IP 连报 3 次只算 1 次；3 个不同 IP 才 hidden；后台能看到举报台账。

**2. 部署配置没有真正注入管理令牌**
- 【代码】`.env.example` 已加 `ZY_ADMIN_TOKEN`，但 `render.yaml` / `fly.toml` 没有对应 secret 项。
- 影响：按现在的配置部署到 Render/Fly，管理接口在公网只能用「本机直连」判定——容器里没有本机，等于管理接口全废；如果为了省事把令牌硬编码进文件，又会进版本库。
- 建议：Render 用 `sync: false` 的环境变量，Fly 用 `fly secrets set`；文档写清生成方式（`node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"`）。

**3. 缺隐私政策 / 用户协议 / 免责声明独立页面**
- 【代码】前端只有个人中心里的零散提示，`web/` 下没有 `privacy.html`；公开上线后这是合规硬伤（尤其是拼车板块会公开展示联系方式）。
- 建议：三份静态页（可直接被 SPA 的页脚链接），内容讲清：收集什么（匿名三元组）、不收集什么（姓名电话简历）、拼车信息的公开范围与删除方式、数据保存期限、联系方式。

**4. 拼车联系方式可被脚本批量抓取**
- 【代码】详情接口无单独频控，只受全局写限流影响（读接口 120/min）。
- 影响：120 次/分钟足够把当前全部帖子的手机号/微信号抓完。
- 建议：详情接口单独按 IP 限流（如 30 次/小时）+ 简单人机校验（同源 Referer 校验或一次性 nonce），或改成 `POST /api/rides/:id/reveal` 并记录访问。

**5. 没有数据库备份**
- 【代码】`server/data/zhiyun.db` 单文件 + WAL，无备份任务；03:00 只做业务清理。
- 影响：一次误删/磁盘故障，岗位库、拼车、画像全没。
- 建议：每日 03:00 用 `db.backup()` 复制到 `data/backups/`，保留 7 份，`/api/health` 里带上最近备份时间。

### P1 · 体验与数据质量

**6. 城市筛选写死 9 个城市**
- 【代码】`web/js/jobs.js` 的 `CITIES = ['全部','武汉','长沙','郑州','合肥','南昌','成都','杭州','深圳']`；而库里有 9 省 12 市，含「恩施土家族苗族自治州」「长春市」等，按钮里根本没有。
- 建议：从 `/api/stats/by-province` 动态生成 Top N 城市，并与省级下拉联动；离线模式从 seed 数据推导。

**7. 列表没有真正分页**
- 【实测】`/api/jobs?pageSize=999` 仍只返回 50 条（后端 `Math.min(50, …)` 截断）；【代码】前端固定 `pageSize=50`，没有「加载更多」。
- 影响：岗位涨到 200 条时，一半人看不到。
- 建议：前端加「加载更多 / 无限滚动」，后端保持 50 上限，页码递增。

**8. 采集器有效产出低，且没有可观测**
- 【实测】当前 100 条岗位里：演示 34、武汉晴川学院 32、人社部 19、其余为历史数据；采集报告显示 mohrss 发现 20 条但全部「库内已存在」跳过，wllm 渲染模式 0 条。
- 【代码】`/api/fetcher/last-report` 有数据但前端没有任何入口展示。
- 建议：个人中心加「数据更新」卡片，展示最近采集时间、各站点新增/跳过/失败数；对「0 条」给出解释（站点限制/已收录），避免用户误判为坏了。
- 另需排查：mohrss 20 条全部命中去重，是 id 生成规则过严（同标题同公司被合并），还是详情抓取失败后回填了占位数据。

**9. 简历只能导 PDF，模板单一**
- 【代码】`web/js/resume.js` 走 `html2pdf`，只有一套 A4 模板；无 Word/Markdown 导出。
- 建议：至少加「简洁型 / 项目型 / 技能型」三套模板切换；Word 导出可用后端 `docx` 库或前端拼 `application/msword` 的 HTML。

**10. 没有收藏 / 投递记录**
- 【代码】岗位卡只有「查看详情 + 投递跳转」，关掉页面就丢。
- 建议：本地加密存 `favorites` 与 `applications`（公司/岗位/投递日期/状态），个人中心加「求职进度」时间线。这是求职工具最容易被感知的价值点。

**11. 搜索没有防抖、没有历史**
- 【代码】`jobs.js` 输入即请求；无搜索历史、无热门搜索。
- 建议：300ms 防抖 + 最近 5 条搜索记录（本地存）。

### P2 · 工程质量

**12. 整个项目没有自动化测试**
- 【实测】`server/package.json` 只有 `smoke`，没有 `test`；冒烟只覆盖「页面能开、卡片数 > 0、Tab 存在、防骗能出结果、manifest 在、无控制台报错」。
- 建议：`node:test` 覆盖 `jobFilter`（虚假岗评分阈值与 flags）、`rideGuard`（手机号/微信格式、禁词、日期边界）、`fraudGuard`（13 类规则命中与「保住半数分」的修正）、`geo`（省市归一化）。这些纯函数最好测，且都是线上最容易出错的地方。

**13. 不是 git 仓库**
- 【实测】项目根无 `.git`，改错无法回滚，也没有 diff 可看。
- 建议：`git init` + `.gitignore`（`node_modules/`、`server/data/*.db*`、`dist/`、`*.apk`、`android/.gradle/`、`android/app/build/`），首次提交后再接 GitHub/Gitee 私有仓库。

**14. 依赖体积与降级**
- 【代码】`playwright` 在 `dependencies`（含浏览器时镜像会大 300MB+）；`fetcher/wllm.js` 渲染模式依赖它。
- 建议：移到 `optionalDependencies`；渲染器不可用时自动降级为 HTTP 抓取并在报告里标注 `render_unavailable`，而不是静默 0 条。

**15. 前端模板是手写字符串拼接**
- 【代码】`jobs.js` 自己实现 `escapeHTML`，`ride.js`/`profile.js` 各自拼 HTML；任何一处漏转义就是 XSS（岗位数据来自外部采集，属于不可信输入）。
- 建议：抽 `web/js/render.js` 统一 `esc()` + 模板函数，或引入 10KB 级别的模板库（需评估离线体积）。

**16. 版本与包信息不同步**
- 【代码】`server/package.json` 的 `name` 还是 `zhiyun-tongzhi-server`、`version` 是 `1.0.0`，与 `config.version`（1.5.1）不一致；`android` assets 靠手工 `Copy-Item` 同步。
- 建议：`package.json` 版本跟 `config.version` 对齐；在 gradle 里加 `syncWebAssets` task，`assembleDebug` 前自动复制。

### P3 · 产品与增长（非必须，但决定它是否真的有人用）

**17. 没有「学校」这一层**
- 民办生的核心场景是「本校/本地区」。建议加「我的学校」选择，岗位列表默认按学校所在城市排序，拼车默认同校优先。
- 数据侧可复用已有的 `university-sites.json`（湖北 7 校联盟）。

**18. 没有分享能力**
- 岗位详情不能生成分享卡片/链接，靠人传人传播效率低。
- 建议：静态站加 Open Graph 标签；岗位详情支持 `#/job/123` 深链；生成一张 9:16 分享图（纯前端 canvas，不依赖后端）。

**19. 无 SEO / sitemap**
- 【代码】`dist/site/robots.txt` 有，但没有 `sitemap.xml`、没有结构化数据（`JobPosting` schema）。
- 建议：`build:site` 顺带生成 sitemap 与岗位结构化数据，静态托管后能被搜索引擎收录——这是「国外网站」最便宜的获客方式。

**20. 无访问统计**
- 现在完全不知道有多少人用、哪些岗位被点开。
- 建议：自建极轻量统计（`POST /api/stat` 记 `{event, jobId, deviceId hash}`，不记 IP），或接隐私友好的 Umami/Plausible（自托管，免费）。

**21. 移动端与无障碍没系统测过**
- 【推测】暗色模式缺失；部分按钮无 `aria-label`；对比度未校验。
- 建议：至少跑一遍 360×640、390×844、768×1024 三档；关键操作加 `aria-label`。

## 四、需要你拍板的三件事

1. **永久站点放哪**：GitHub Pages（免费、需登录授权一次）还是 Cloudflare Pages（国内访问通常更稳、也需登录）。助理无法代你登录账号，但可以在你登录后把发布流程跑完。
2. **要不要现在 `git init`**：会在项目根新建 `.git`，之后所有改动可回滚；不做的话，ZCode 多轮开发很容易互相覆盖。
3. **是否要独立域名**：`trycloudflare.com` 的临时地址每次重启都变，只适合演示；正式对外需要一个固定域名（Cloudflare 免费额度即可，域名本身约几十元/年）。
